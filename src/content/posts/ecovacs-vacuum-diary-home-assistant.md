家裡的科沃斯掃地機器人通常都被我關在家裡，房間不大，
週末想到的時候按下開始，它掃完自己回座充電，我再倒一下集塵盒。
整個流程沒有什麼不方便，所以它雖然早就接進 Home Assistant，我卻幾乎沒有替它做過任何設定。
前陣子我開始好奇，既然它都已經在 Home Assistant 裡了，到底還能做什麼？
我請Claude幫我把它在系統裡的實體與服務全部翻出來，整理成一份可以玩的清單。
清單很完整，出門自動開掃、卡住推播、週末自動加拖地、掃完通知……每一項都合理，但我看完的感想只有一句：**都很無聊。**
所以最後我沒有替它多加任何實用的自動化，倒是讓它每天晚上用秘書的口吻，跟我回報這一天做了什麼。

## 先看看它在 Home Assistant 裡能做什麼

我的掃地機器人是用 [Matter](https://www.home-assistant.io/integrations/matter/) 接進 Home Assistant 的，沒有用科沃斯官方整合，
Matter 可以想成一套跨品牌的共同語言，不同廠牌的設備都用同一種方式被控制。
好處是走本機連線，也不用登入科沃斯帳號，代價是只能用 Matter 規範裡有的功能。
整理下來，能控制的大概是這些：
- 開始、暫停、停止、回充，還有讓它發出聲音的「找機器人」
- 清潔模式三選一：只掃、掃拖同時、先掃後拖
- 分房清掃（`vacuum.clean_area`）有支援，但要先把機器人地圖上的房間對應到 Home Assistant 的區域
- 吸力調整沒有，Matter 裡看不到這一項

能讀到的資料倒是比我想的多。電量、充電狀態、運作狀態都有，還有一個錯誤感測器，卡住、集塵盒滿、水箱沒水、主刷纏住等十幾種狀況都會回報。
讓我眼睛一亮的是另一個「目前動作」感測器，選項有 30 種，一般清掃、回座集塵、洗拖布、烘乾拖布，連迷路後重新定位都有，
也就是說，Home Assistant 除了知道它在掃，還知道它掃到一半跑回去倒了幾次垃圾、幾點迷路。
這些資料平常根本沒人看，但整串讀下來，就是它一天的工作流水帳。
## 一週掃一次，實用的自動化都用不太到

第一輪整理出來的點子，大多是網路上很常見、也真的有人在用的：
- 全家出門後自動開掃，有人回家就回充；
- 卡住、水箱沒水或集塵盒滿時推播到手機；
- 平日只掃，週末改成先掃後拖；
- 掃完回座時通知「清潔完成」。

我在[遙控和自動化的差別](/smart-home-vs-remote-control)那篇裡，判斷一件事值不值得自動化，看的是它是不是每天重複、觸發條件清不清楚。窗簾每天早上要開、冷氣每天凌晨要關，寫成規則很划算。
掃地剛好相反，我一週其實才掃一次，除非真的自己把家裡搞得非常髒，時間其實也不固定，按下開始對我來說根本不麻煩。
改成「離家自動開掃」，一週也才省下一次按按鈕，為了讓規則可靠，還要處理有人在家、門沒關、機器人被叫回去這些例外，想到就覺得麻煩。
後來 Claude 換了個方向，只留下三個讓手動更順的小東西：滿七天提醒、掃完通知、一句話開掃，
比較實際了，但我還是覺得無聊，我想要好玩一點的。

## 讓它開口說話：掃地人日記

所以我請AI給我主意，下一輪的點子就放飛多了，讓 AI 把它的動作講成球賽實況、做一張會換表情的電子雞卡片、設計「連續四週出勤」這種成就系統，或是讓它用自己的口吻寫日記。
我選了日記，每天一篇不吵，又剛好用得上那 30 種動作狀態。

### 第一版：沒有 AI，只好先寫好台詞

動手之後才發現，我的 Home Assistant 根本沒有接任何 AI 整合。所以第一版日記是一個自動化在清掃過程中記幾件事，掃完再從寫好的台詞裡隨機挑來組合：
- 開始清掃時，記下開始時間，清空這次的事件紀錄；
- 中途卡住、迷路或出現其他錯誤，就把代碼加進事件紀錄；
- 回到座上時，算出掃了幾分鐘、讀當下的清潔模式，再把事件代碼翻成一句話。

事件翻譯大概長這樣，每個錯誤都配一句它自己的抱怨：
```jinja
{% set map = {
  'stuck': '中途卡住了，原地轉了好久，好丟臉。',
  'relocation': '還迷路了一下，重新認路才找回來。',
  'dust_bin_full': '肚子塞滿了（集塵盒滿了），求清。',
  'water_tank_empty': '水喝光了，拖到一半口好乾。'
} %}
```

這裡有個小陷阱，暫停之後繼續掃，機器人的狀態會再變回「清掃中」。
如果每次進入清掃中都重設開始時間，有暫停過的那次就會被算短。所以我另外用一個開關記住「這一輪已經開始記了」，還沒開始才重設。
這一版能跑，但台詞是固定的，玩幾次就開始重複，它也不會記得上週發生什麼事。

### 日記要放在看得到的地方

一開始日記只會推播到手機，另外寫進 Home Assistant 的日誌，
新版介面把日誌改名叫「活動」，我自己在選單裡找了半天才找到，放在那裡大概沒人會去看，
所以我把它搬到儀表板最上面，做成一整排的區塊。
中間還改過一次，原本區塊裡列出最近所有日記，看起來很像系統紀錄，後來改成首頁只放最新一篇，下面一顆「看更多日記」按鈕，點進去才是完整的日記本。

有兩個小細節。日記如果直接掛在掃地機器人身上寫進日誌，會跟「開始清掃」、「回到座上」這些狀態變化混在一起，所以我另外建了一個專門收日記的「日記本」實體。另外，首頁那一篇是存在文字輔助元件裡，最多只能放 255 個字，每篇日記都得控制在這個長度內。

## 改成每晚十點由 Claude 讀紀錄來寫

隨機台詞玩一下就膩了，我想看的是照它那天實際做了什麼寫出來的日記。
我請 Claude 回頭翻之前的歷史紀錄，寫成正式的第一篇，紀錄裡的細節比我記得的多很多。
傍晚六點它先掃後拖，掃到一半兩度回座集塵、洗了一次拖布，前後 42 分鐘才結束，最後還烘乾拖布五分鐘，
晚上八點多我又按了一次只掃，它出門 42 秒就被我叫回去，一分鐘後再被派出去補掃 8 分鐘。
這些事我當下完全沒注意，寫成日記之後反而很好笑。

之後就交給我電腦上 Claude 的排程任務。每晚 22:00 它會：
1. 讀前幾篇日記，記住語氣和前幾天發生的事；
2. 從 Home Assistant 讀當天掃地機器人的狀態、細部動作、錯誤和清潔模式；
3. 寫一篇日記，更新儀表板上的最新一篇、日記本和篇數，再推播到手機。

沒掃地的日子也會有一篇，只是變成短短的「待命日報」。
如果晚上十點電腦沒開，下次開機會補寫前一天；好幾天沒開，就把那幾天合成一篇，代價是它要靠我的電腦。
我本來想改到雲端跑，但我的 Home Assistant 只在家裡網路內，沒有開外部連線，雲端碰不到它。
要搬上雲端得先處理對外連線和權杖授權，為了一篇日記我覺得不值得，就接受「電腦開著才寫，沒開就補寫」。
還有一個限制，Home Assistant 的詳細歷史大約只留十天，所以補寫也有上限。

10/31 那篇最後長這樣：
> Boss，向您回報今日工作：共出勤兩趟。
> 18:00 先掃後拖 42 分鐘，途中集塵盒爆滿，兩度返航倒垃圾並清洗拖布，結案後烘乾 5 分鐘。
> 20:45 指派只掃模式，出發 42 秒即被召回，一分鐘後再度派遣，補掃 8 分鐘完成。
> 全日零失誤。本秘書建議下次指令一次講清楚，不過能幫上 Boss 的忙，我還是很開心的啦～

同樣的數字、同樣的事件，用系統紀錄的口吻寫，我大概看一次就關掉了。
換成一個會吐槽「指令一次講清楚」的秘書，我反而每天都想點開看它今天又要說什麼。

## 一週只上班一次的設備，需要的是別的東西

回頭看，這大概是整個系列裡最沒效率的一個自動化，它沒幫我少按任何一次按鈕，我還是一週手動掃一次。
但我現在知道它哪天中途回座集塵兩次、哪天被我叫回去又派出去，這些資料一直都在 Home Assistant 裡，只是以前沒有一個我會想看的樣子。
前面幾篇我在意的都是怎麼讓家自己動起來，這次讓我發現，像掃地機器人這種一週才用一次的設備，比起多一條規則，我更需要的是一個讓我想去看它在幹嘛的方式。
至於我家這台，現在每天晚上十點都會準時跟 Boss 報到。
