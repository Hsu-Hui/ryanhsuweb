上一期的電費單寄來，總額 3,674 元，我只知道夏天冷氣開得兇。
帳單上另外有一筆公共設施電費 1,457.4 元，等於扣掉大樓分攤的部分，我家自己用了 849 度、兩千多塊。
問題是，我完全說不出這 849 度花在哪裡。

家裡三台冷氣、十幾個燈的開關、除濕機和風扇都已經接進 Home Assistant，按理說它最清楚我什麼時候開了什麼。
所以我先請 Claude 幫我翻 Home Assistant 裡所有跟用電有關的東西，結果一個都沒有。
名稱裡有「電」的實體只有三個，掃地機器人的電量、充電狀態，還有電視盒的連線模式，沒有一個是在量用電。

一般的解法是裝智慧電表或電流夾，但這條路我走不了。
既然量不到，我就退一步：Home Assistant 量不到「用了多少電」，卻記得「冷氣開了多久」。

## Home Assistant 量不到電，但記得冷氣開了多久

第一輪盤點除了確認沒有電表，還翻出一個限制：Home Assistant 的詳細歷史大約只留十天，三台冷氣最早的紀錄是 10/26。
我原本想回頭算 7 到 9 月那期為什麼那麼貴，這下也算不了。

能查到的 10/26 到 11/05，三台冷氣都是冷房模式，設定溫度大多是 26°C，加起來的開機時數是這樣：

| 冷氣 | 10/26–11/05 開機時數 |
|---|---|
| 客廳 | 約 7.4 小時 |
| 臥室 | 約 33.9 小時 |
| 書房 | 約 16.8 小時 |

臥室冷氣幾乎都是半夜開，到凌晨四點被我在[遙控和自動化的差別](/smart-home-vs-remote-control)那篇提過的規則關掉。
臥室開得最久，33.9 小時，比另外兩台加起來還多。
這些時數就是估算的起點：冷氣開著的每一分鐘，都乘上一個平均功率，累加起來就是度數。

## 把開關狀態換算成度數

我給 Claude 的需求很簡單：依照我開冷氣的時間去算，再加上電燈這些，做一個儀表板看每天用電、預估用電和電費。
它把整個估算拆成三層，每一層都是 Home Assistant 內建的輔助元件，不用寫 YAML，也不用裝額外整合。

### 第一層：設備開著，就給它一個瓦數

每台冷氣配一個可調的「平均功率」：客廳 900 W、臥室 600 W、書房 700 W。
這裡刻意不用冷氣的額定功率。變頻冷氣降到設定溫度後會慢下來，整段開機時間的平均耗電比銘牌上的數字低很多，所以我填的是「冷房模式下大概的平均值」，之後再拿帳單修正。

接著用 template sensor 判斷冷氣狀態，冷房、除濕、暖氣都算開著，開著就等於那個瓦數，關著就是 0：

```jinja
{% set on = states('climate.ke_ting_kong_diao_thermostat') in ['cool', 'dry', 'heat'] %}
{{ ((states('input_number.dian_fei_gu_suan_ke_ting_leng_qi_ping_jun_gong_lu')|float(0) if on else 0)
    * states('input_number.dian_fei_gu_suan_xiao_zheng_xi_shu')|float(1)) | round(1) }}
```

燈具也是同樣的做法，19 個燈或開關迴路各配一個瓦數，先全部當成 10 W 的 LED，開著的加總起來。除濕機 250 W，風扇、循環扇和空氣清淨機各 30 W。

剩下的冰箱、熱水、電腦和各種待機，Home Assistant 完全看不到，就用一個「基本負載」概括，先設每天 4 度，換算成全天候固定約 167 W。

### 第二層：瓦數乘上時間，變成度數

功率只是一個瞬間的數字，要變成度數，得乘上時間。
Home Assistant 內建的 [Integration](https://www.home-assistant.io/integrations/integration/) 輔助元件就是做這件事，它會把功率對時間累加，算出累計的 kWh。客廳冷氣、臥室冷氣、書房冷氣、燈具、其他設備、基本負載和總計，各有一個累計度數。

### 第三層：切成今天和這一期

累計度數會一直往上加，看起來不直覺，所以再用 [Utility Meter](https://www.home-assistant.io/integrations/utility_meter/) 切成「今日度數」和「本期度數」。
今日每天半夜歸零；本期則跟著台電的雙月抄表走，另外有一條自動化在抄表日 00:00 把本期歸零，順便把下次抄表日往後推兩個月。

還有一個小陷阱：校正係數一開始只乘在總計上，這樣各來源加起來會對不上總數。
後來改成乘在每個來源的功率上，加起來才剛好等於總計。

## 台電的累進電價，比度數本身還難算

有了度數，下一步是換成錢，台電住宅用電是累進制，雙月計費的級距是每月級距乘二：前 240 度一個價，241 到 660 度更貴，之後一路往上。

麻煩在於夏月，6 月到 9 月用夏月電價，其他月份用非夏月電價，而我這一期從 9/17 抄表到 11/18，62 天裡有 14 天落在 9 月。
這種橫跨兩種電價的期間，就按天數比例混合兩種算法，所以儀表板上另外有一個「本期夏月天數比例」，目前是 22.6%。
電費感測器做的事，其實就是把度數一格一格填進級距：

```jinja
{% set lim = [240, 660, 1000, 1400, 2000, 999999] %}
{% set ps = [1.78, 2.55, 3.80, 5.14, 6.44, 8.86] %}  {# 夏月 #}
{% set pw = [1.78, 2.26, 3.13, 4.24, 5.27, 7.03] %}  {# 非夏月 #}
{% for i in range(6) %}
  {% set q = [[kwh, lim[i]]|min - b.prev, 0]|max %}
  ...
{% endfor %}
{{ (f * b.s + (1 - f) * b.w) | round(0) }}
```

電價是我提供的數字，Claude 另外上網核對過，跟 2026 年的住宅電價一致。
有了這個，儀表板就能算出幾個我真正在意的值：本期電費至今、整期預估帳單、目前每多用一度要多付多少錢（邊際單價），以及距離下一個更貴的級距還剩幾度。

## 前半期沒有紀錄，只能先回推

估算是 11/5 下午才開始跑的，但這一期從 9/17 就開始了，中間這一個多月沒有任何追蹤，本期度數直接從 0 起算的話，預估帳單會低得很不合理。
Claude 的做法是用 10/26 之後能查到的實際開關時數，算出平均每天約 9.1 度，往回推到 9/17，得出約 451 度，存成一個「追蹤前補估度數」，加在本期度數前面。
這個數字它自己也標了風險：9 月底比 10 月熱，實際大概更高。所以它是一個可以手動改的參數，下次抄表時由自動化歸零，不會影響下一期。

## 拿帳單對帳：公式對了，估算還沒有

做完第一版，我把電費單拍照丟回去，讓它跟儀表板比對。

帳單上 7/17 到 9/16 那一期，計費 849 度，流動電費 2,216.4 元。
這期整段都是夏月，849 度填進級距是 240 × 1.78 + 420 × 2.55 + 189 × 3.80，剛好 2,216.4 元，電價公式和台電算的完全一樣。

不過這次對帳證明的只有「度數換成錢」這一段。至於「冷氣開幾小時換成幾度」準不準，要等 11/18 這期的帳單出來才知道。
到時候用帳單上的實際度數除以儀表板估的本期度數，填進「校正係數」，之後每個來源都會乘上它。在那之前，這個儀表板上的度數都還是推估。

## 估得不準，也能用來守住預算

度數本身還不準，拿它來回答「這期到底花了多少」意義不大，但拿來算接下來還能用多少，已經夠用。
所以我給它定了一個目標：這期總帳單不要超過 3,000 元，總是需要開始省錢吧？
反過來算，扣掉公共電費、套上混合的累進電價，3,000 元大約能用 702.4 度。
本期已經用了約 452 度，剩下 12 天左右，平均每天可以用 20.5 度，其實平日都不在家，只有假日會在家才會花多一點。

這些數字放在「電費估算」儀表板最上方，預估在目標內是綠框，超標就變紅框。
另外有一條「電費估算 超標提醒」自動化，每天晚上 21:00 檢查一次，預估總帳單超過 3,000 元，或昨天的度數超過每日可用度數，就發一則通知，附上像是「臥室冷氣從 26°C 調到 27°C」「提早定時關機」這類建議。

上一篇寫的掃地人日記，同一天也被我改成了「智能管家日記」，每晚的日記裡一定有一段用電報告：昨天用了幾度、哪台冷氣開最久、離 3,000 元還差多少，再附一句省電建議。
不用特地打開儀表板，每天也會看到一次自己的用電狀況。

## 這些數字還有哪些盲點

這套估算有幾個我自己也知道的缺口：

- 吸頂燈沒算進去，三間房的吸頂燈在 Home Assistant 裡一直顯示離線，看起來是靠牆壁開關供電，跟開關迴路算兩次會重複，所以只算開關那一側。如果某個開關其實沒接燈，要記得把瓦數改成 0。
- 冷氣功率是平均值，同樣開一小時，悶熱的下午和涼爽的半夜耗電差很多，這裡全部用同一個數字。
- 基本負載是猜的，冰箱、熱水和電腦這些，每天 4 度只是起始值，帳單出來前沒有依據。
- 開始的數字偏低，追蹤從 11/5 下午三點才開始，今日度數和近 30 天折線圖都要從隔天起才有完整資料。

這些都可以在儀表板最下面的「調整參數」區改，改完所有估算會跟著變。

## 量不到的東西，先估一個能修正的版本

一個有公式、有假設、可以拿帳單修正的估算，至少讓我知道那十天裡臥室冷氣開了將近 34 個小時，比另外兩台加起來還久。
數字準不準，11/18 抄表後就會知道第一次答案。
做這麼多就是想在台電APP裡面可以猜到時候用電用幾度，讓我有辦法可以省電費~
