上一篇讓舊 iPhone 6s 變成桌上的音樂中控台，原因單純是我喜歡一邊聽 YouTube Music 一邊看歌詞。

後來在 GitHub 看到 [Folia](https://github.com/chthollyphile/folia-major)，一個主打全螢幕動態歌詞的第三方音樂播放器，支援 YouTube Music，畫面很好看，好看到我開始懷疑自己是不是需要它。

## 先評估，再安裝

### 它提醒我的風險

我原本只想問「能不能用」，Codex 順便列了一張風險清單，我覺得比安裝步驟更有價值：

- **安裝檔沒有 Windows 數位簽章。** 它從 GitHub Releases 下載後，先比對官方 SHA-256，一致才安裝。
- **Folium 模組沒有沙箱。** 主程序模組擁有完整 Node.js 權限，來路不明的模組不要裝。
- **YouTube Music 是非官方整合。** YouTube 改了什麼，登入或播放就可能突然失效。
- **AI 主題會把歌名和部分歌詞送到雲端。** 不開就不會送。
- **本機 API 預設不要開。** 歌詞介面開啟後，會在 `127.0.0.1` 提供不需驗證的資料。

### 安裝前，先備份 YouTube Music

我平常用的是 Chrome 安裝的 YouTube Music PWA。Folia 理論上不會碰它，但「理論上」這三個字我聽過太多次了，所以請 Codex 先備份。
它只備份了捷徑、圖示、App ID 和重裝步驟，刻意不碰 Cookie、登入 Token 和整個 Chrome 個人檔案。歌單和喜歡的歌本來就在 Google 雲端，真的壞了重新登入就好。安裝完成後，它還比對了一次捷徑雜湊，確認 YouTube Music 沒有被動到。

## 開始用之後才遇到的事

### 登入成功，但視窗說還在等

第一次登入 YouTube Music，Folia 的視窗一直停在「等待瀏覽器確認」。Codex 去看本機資料，發現登入其實早就成功了，連首頁和歌單都讀到了，只是視窗沒有跟上。關掉重開就好。

### 有些歌就是沒有歌詞

YouTube Music 有時會選到 MV、Fancam 這類影片版本，而不是正式的歌曲版本。影片版常常配對不到歌詞，或歌詞時間對不上。這是 Folia 目前已知的限制，換一個有專輯封面的歌曲版本通常就解決了。

## 接上 Ollama，讓每首歌有自己的配色

Folia 的 AI 不是拿來生成音樂的。它會讀歌名和部分歌詞，推測歌曲氣氛，再產生一套配色、強調色和裝飾圖示。悲傷的歌給深藍灰，輕快的歌給暖色系。

我電腦裡本來就有 Ollama，平常用雲端的 `gpt-oss:120b`，所以想直接接上，這段有一個值得記下來的轉折。

### 一開始：直接把金鑰貼進去

最直覺的設定是 API 地址填 `https://ollama.com/v1`，再把真實的 Ollama API Key 貼進 Folia。
我問 Codex：「把金鑰貼進這個介面會不會有危險？」它的回答是可以，但更建議不要。Folia 是第三方程式，執行時有能力解密並使用金鑰；如果哪天裝了惡意模組，金鑰就可能被拿走。

### 後來：讓本機 Ollama 當中間人

比較安全的做法是讓 Folia 連本機的 Ollama，由已登入的 Ollama 轉送到雲端：

```text
供應商：自訂相容接口
接口地址：http://127.0.0.1:11434/v1
密鑰：ollama
模型：gpt-oss:120b-cloud
```

這裡的 `ollama` 只是佔位字串，本機介面會直接忽略它。真正的金鑰從頭到尾沒有交給 Folia。

### 401 和一個誤會

設定完按「測試連接」，得到 `HTTP 401`。原因有兩個：當時 Ollama 根本沒在執行，以及 Folia 的地址欄其實還是雲端網址，假密鑰被送到需要真密鑰的地方，當然被擋。

修正過程中，Codex 叫我跑 `ollama pull gpt-oss:120b-cloud`。我愣了一下，以為要把 65 GB 的模型下載到本機。其實 `-cloud` 版本只會登記一筆模型資訊，權重仍在雲端，`ollama ls` 裡它的大小會顯示 `-`。
啟動 Ollama、改對地址之後，AI 主題就成功產生了。

## 第一個模組-歌詞簡體中文轉繁體中文

主題有了，但歌詞來源大多是簡體中文，Folia 的介面語言可以切繁體，但只改選單，不改歌詞。

Codex 建議不要用 AI 逐首翻，太慢、會花額度，還可能破壞逐字時間軸，
它的做法是寫一個 Folium 模組，用 [OpenCC](https://github.com/BYVoid/OpenCC) 在歌詞顯示前做「簡體轉臺灣繁體」，字典直接打包進模組，完全離線。

- 不呼叫任何 AI，不花額度
- 保留逐字時間、和聲與翻譯
- 不修改原始歌詞，關掉模組就恢復

## 第二個模組-歌詞製造器

接著我問了一個聽起來很合理、做起來很不合理的問題：

> 有沒有辦法做一個模組，如果沒有歌詞的話可以幫我產生歌詞？

`gpt-oss` 是文字模型，聽不到歌，所以主角換成本機的 Whisper。Codex 選了 whisper.cpp 搭配 `large-v3-turbo` 模型，用 RTX 4070 Ti SUPER 跑 CUDA。測試時 11 秒的語音約 1.5 秒就辨識完。

### 先講好退場機制

我只提了三個條件：模型放在哪、可以關、日後不想用要知道怎麼刪。結果是：

- 模型和執行環境集中在一個資料夾，長期約佔 2.65 GiB
- 暫存音訊轉錄完就刪，只留很小的 VTT 歌詞檔
- 預設手動產生，不會每首歌都偷偷吃 GPU
- 移除時刪掉模組資料夾和那個資料夾就好

後來我又請它把「替目前歌曲產生歌詞」按鈕做進播放器的控制面板，
Folium 不允許模組改內建的歌詞分頁，所以它開了一個相鄰的「本機歌詞」分頁。

### 抓不到音訊

第一版按下去，畫面一直停在「等待重新載入歌曲」。Codex 去拆了 Folia 的程式包，找到兩個原因：
1. 切回播放過的歌時，Folia 直接沿用快取，不會再發出音訊網址事件。
2. YouTube Music 在 Folia 裡不是一般的 `https://` 網址，而是自己的 `folia-ytm://` 串流，舊版模組只收 HTTPS。

最後改成直接從畫面端讀取正在播放的串流，問題解決。

### 模型幻覺

第一首成功轉錄的是一支 Fancam。歌詞從頭到尾都是同一句：

> 優優獨播劇場——YoYo Television Series Exclusive

這是 Whisper 的幻覺，音樂太大聲、人聲不清楚時，它會從訓練資料裡挑一句常見的字幕浮水印補上去，它沒有看畫面，純粹是聽不懂，然後很有自信地亂寫。
換一首正式錄音室版本，前段歌詞就準了，但只準到第一遍副歌，之後整首一直重複「作曲：李宗盛」，一共 18 次，原因是 Whisper 會拿前面的結果當提示，一旦選中一句錯的，就一路錯下去。

### 越修越糟，然後回退

接下來幾版的經過，大概是這樣：

| 版本 | 做了什麼 | 結果 |
| --- | --- | --- |
| 0.3.1 | 關閉前文延續、關閉高溫重試、預設中文、偵測連續重複 | 比之前好，但有同音字錯誤 |
| 0.3.2 | 改成有限上下文 | 品質檢查太嚴格，整首判定失敗，乾脆不存 |
| 0.3.3 | 品質檢查改成只刪壞掉的段落，不整首丟掉 | 前 30 秒整段消失 |
| 0.3.4 | 撤回有限上下文 | 回到 0.3.1 的水準 |
| 0.3.5 | 開頭超過 10 秒沒歌詞時，只針對前段再辨識一次 | 測試中 |

0.3.3 那次我直接說「越改越糟了」。Codex 的回應是承認問題出在它上一版加的有限上下文，把前 30 秒合併成一個幻覺區塊，清理器只好整塊刪掉，然後先回退，不在錯誤上繼續疊修正。

好吧，只好持續優化中，一部份辨識效果沒這麼好是因為我一直聽R&B版本的歌，能辨識完全正確才有鬼。

### 還沒解決的部分

- **同音字**：「事過境遷」還是有機會變成「試過今天」。用 `gpt-oss` 做保守校正可以改善，但 Folium 目前沒有把 AI 設定開放給模組，Codex 不打算用非官方方式讀我的金鑰，所以暫時沒做。
- **漏字**：「溫熱的咖啡杯」會變成「溫熱的咖啡」，句尾常被伴奏蓋掉。
- **時間差**：Whisper 給的是整句時間，對不到每個字。Folia 本身有每首歌的歌詞偏移設定，先用這個手動微調。
- **現場版**：觀眾尖叫和混響會讓辨識幾乎失效。要改善得先做人聲分離，我決定先不做。

另外提醒一下，這些自動產生的歌詞只放在我自己電腦裡看，歌詞著作權仍屬於原作者，不要拿去分享。

## 最後的成果

整理一下這個晚上的產出：
- Folia 安裝，YouTube Music 正常登入與播放
- AI 主題透過本機 Ollama 轉送到 `gpt-oss:120b-cloud`，金鑰沒有交給 Folia
- OpenCC 繁體歌詞模組，離線、不花額度
- 本機 Whisper 歌詞模組，能替大部分錄音室版本產生還算可用的歌詞

如果你也想試 Folia，我的建議是：先用 Realeco 正式版，先不要開模組和本機 API，AI 主題能走本機 Ollama 就不要直接貼金鑰。

至於 Whisper 模組，它目前最穩定的功能是讓我知道哪些歌的前奏特別長。
